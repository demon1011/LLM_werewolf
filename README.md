# 🐺 LLM Werewolf — 基于经验记忆的自进化狼人杀多智能体系统

这是一个实验性框架,想验证一件事:一组 LLM 智能体能不能**只靠自我反思**,在**没有任何人类专家指导**、也**不微调模型权重**的情况下,把游戏胜率提上去。

智能体不改动自身参数,而是把每局打完后总结出的经验用自然语言存下来,一局一局地**积累、提炼、再复用**。所有能力提升都发生在上下文与记忆层面,模型本身始终不变——可以把它看作一种轻量的、发生在经验层面的**递归自我改进(Recursive Self-Improvement, RSI)**。

## ✨ 核心亮点

- 🧠 **记忆增强的 Off-Policy 自我改进** —— 智能体学习的对象,是从所有历史对局中沉淀下来的一个共享经验池,而不只是自己上一局的表现。这也是它区别于 Reflexion 这类 on-policy 方法的关键。
- 🔁 **经验层面的 RSI,不动权重** —— 能力提升全靠**上下文工程**:反思 → 提炼 → 存储 → 检索 → 复用,五步闭环,底座模型始终冻结。
- 🗳️ **用 Self-Consistency 让归因更稳** —— 每次失败归因都采样 `k=8` 次,只有当**超过 60%** 的结果一致时才采信,把不靠谱的判断挡在记忆之外。
- 🧩 **经验结构化,而且能泛化** —— 每条经验都以 5 个字段的固定结构存储,并强制**不带任何具体玩家编号**,这样它才能迁移到之后的对局里,而不是只适用于当时那一局。
- 📈 **收益可以量化** —— 全程没有一条人工写的策略;仅凭自己总结的经验,好人方胜率相比无记忆基线提升 **+13.5%**,狼人方提升 **+11%**。

---

## 🎯 研究动机

目前做「自进化智能体」大多走两条路:要么微调权重,要么用 on-policy 的自我反思(比如 Reflexion),让智能体去修正自己刚刚走过的那条轨迹。本项目想问的是一个更小、也更干净的问题:

> **一个被冻结的 LLM,能不能只靠自己写给自己的经验,在复杂的多智能体社交推理博弈里越打越好?**

选狼人杀做试验场有几个理由:它需要隐藏身份的推理、需要欺骗、需要结盟,还需要对很长的一局做责任归因;同时它的胜负结果本身就是一个明确的奖励信号,而整个过程又没有任何「标准答案」可供参照。这些特点让它很适合用来研究无监督的自我改进。

---

## 🏗️ 系统如何运作

系统围绕一个**冻结的底座 LLM** 运行一个完整的**经验闭环**:

```
        ┌─────────────────────────────────────────────────────────┐
        │                    共享经验池                            │
        │            (结构化建议,持久化存储于磁盘)               │
        └───────────────▲─────────────────────────────┬───────────┘
                        │ 存入(提炼后的经验)         │ 检索(按角色/环节/技能)
                        │                               ▼
   ┌────────────────────┴────────┐        ┌────────────────────────────┐
   │        赛后自我反思          │        │         对局内决策          │
   │   (责任归因 + 经验提炼)     │◄───────│   8 个角色条件化智能体      │
   │                              │  败局  │   + 信息隔离                │
   └─────────────────────────────┘        └────────────────────────────┘
```

### 1. 对局内:角色条件化的多智能体博弈

- **8 个智能体,共用一个冻结模型。** 8 名玩家其实是同一个 LLM 的 8 个独立实例,彼此的区别只在于**各自角色的系统提示**(预言家 / 女巫 / 猎人 / 2 村民 / 3 狼人)。
- **严格的信息隔离。** 每个角色能看到什么,由一个按角色过滤的日志系统决定:狼人能看到夜晚商议,预言家能看到自己的验人结果,女巫能看到自己的用药记录,村民则只能看到公开发言。这样一来,推理就必须靠真实的博弈,而不是靠信息穿帮。
- **分阶段推进。** 白天依次发言(后发言的人能看到前面所有发言)→ 白天投票 → 夜晚狼人商议并击杀 → 各角色使用技能(查验 / 解药 / 毒药 / 猎枪)。
- **经验注入。** 每到一个决策点,系统会检索出相关的历史经验,以 `<建议>…</建议>` 的形式拼进提示词。也就是说,智能体是**带着以往的经验**在做每一个决定。

### 2. 赛后:自我反思与经验提炼

每局结束后都会触发一次反思,而且只针对**输的那一方**做归因:

**第一步:责任归因(配合 Self-Consistency)。** 把整局日志重新喂给模型 **8 遍**(`temp=0.5`),每遍都让它回答*「失败方里谁的责任最大、为什么」*。8 个回答做一次多数投票,只有当**超过 60% 的采样指向同一个人**时,才据此提取经验;否则这一局就不产出任何记忆。归因是整个流程里上下文最长、最容易出幻觉的一步,这道投票正是专门为它加的一层过滤。

**第二步:经验提炼。** 把上一步确认下来的失误点,提炼成一条结构化的经验。

### 3. 记忆:结构化、经校验、可泛化

每条经验以 **5 字段结构**存储:

| 字段 | 用途 |
|------|------|
| `角色职业` | 经验适用的角色 |
| `游戏建议` | 提炼出的可执行建议 |
| `游戏环节` | 天数与昼夜阶段 |
| `游戏技能` | 具体的决策类型(发言 / 投票 / 毒药 / …) |
| `游戏局面` | 适用的局面状态 |

存进记忆之前,每条经验都要过一道校验:

- ✅ 五个字段齐全,取值都在允许的范围内
- ✅ **不绑定具体玩家** —— 一旦建议里出现具体编号就直接打回,逼着经验往通用的方向写
- 🔁 格式不对最多重写 3 次
- 🧷 **去重与归并** —— `(角色, 环节, 技能)` 相同的经验会合并到一起,而不是各存一份

这也是为什么 **350 局最后只沉淀出 295 条经验**:这条流水线会主动过滤和归并,而不是把每局都原样记下来。

### 4. 检索与复用(Off-Policy)

每到一个决策点,系统就拿**当前的 `(角色, 环节, 技能)`** 去共享经验池里找匹配的建议,再注入提示词。关键在于:这个池子汇集的是**所有玩家、所有历史对局**的经验。所以今天这一步棋,完全可能用上另一个智能体在另一局里踩过的坑总结出的教训。**正是这种跨对局、跨智能体的复用,让整个学习过程成为 off-policy**,也把它和 on-policy 的自我反思区分开来。

---

## 📊 实验结果

智能体从**零人工策略**起步,自我对弈打了 **350 局**,沉淀出 **295 条经过校验的经验**。然后每次只让一方启用经验检索,和完全没有记忆的基线做对比:

<p align="center">
  <img src="./assets/总胜场.png" alt="胜率对比" width="640"/>
</p>

| 设置 | 相比基线的胜率提升 |
|------|:------------------:|
| 🧑 好人方使用提炼出的经验 | **+13.5%** |
| 🐺 狼人方使用提炼出的经验 | **+11%** |

可以看出:**这些由智能体自己写下、无人监督的经验,不管是在偏合作的好人一方,还是在偏对抗、需要欺骗的狼人一方,都带来了可量化的提升**,而这一切都没有动过模型权重。

相关主题:*记忆增强智能体、智能体自我改进、经验式 / 测试时学习、self-consistency、上下文工程,以及轻量的(经验级)递归自我改进(RSI)。*

> **说明一下边界:** 这里说的「RSI」,指的是**经验和记忆层面**的自我改进,并不是去递归地改写模型自身的权重或架构。整个过程中,底座模型始终是冻结的。

## 🎲 游戏规则(简化版狼人杀)

- **8 人局:** 3 神(预言家、女巫、猎人)+ 2 村民 + 3 狼人;狼人的胜利条件为屠单边(灭掉神职或村民任一侧)。
- 没有竞选警长与移交警徽流环节。
- 白天投票平票时,随机消灭其中一位玩家(不设二次辩论)。
- 猎人无论因何原因出局,只要游戏未结束,均可触发猎枪复仇技能。

## 🚀 快速开始

```bash
# 克隆仓库
git clone https://github.com/demon1011/LLM_werewolf.git

# 进入项目目录

pip install -r requirements.txt

python -m main
```

## 🗺️ 未来工作

- **平衡探索与利用** —— 改进策略采样,让那些有潜力但还很少被用到的经验也有机会被试上一试。
- **抑制过拟合** —— 识别并剔除那些只对特定对手或特定配置有效、其实已经过拟合的经验。
- **提升检索质量** —— 从现在的标签过滤,升级到按相关性排序的 top-k 检索,并为记忆做更丰富的索引,让智能体真正看到的那几条经验更贴合当前局面。
- **持续积累** —— 在更大规模的对局上扩充经验池,观察收益能否随对局数一起滚起来。

## 📁 项目结构

|------|------|------|
| 主入口 | `main.py` | 游戏循环 + 赛后反思 |
